FakeDiscord ConPTY — нативный терминал для Tincan
=================================================

Это экспериментальная нативная версия FakeDiscord без Windows Terminal,
без .NET, Qt и Electron.

Что внутри
----------
- Native C++ / Win32.
- Встроенный tincan.exe.
- Windows ConPTY (Pseudo Console).
- Собственный минимальный VT/ANSI-рендерер.
- UTF-8 / Unicode.
- 16/256/TrueColor ANSI-цвета.
- Alternate screen.
- Cursor movement / clear / scroll / SGR.
- F1-F12, стрелки, Home/End, PgUp/PgDn, Insert/Delete.
- Ctrl+A...Ctrl+Z.
- Кнопки мышкой:
    F2 Talk
    F3 Mute
    F5 Deafen
    F6 Audio
- Иконка FakeDiscord прямо в шапке окна.
- Ник сохраняется в:
    %APPDATA%\FakeDiscord\nick.txt
- Быстрое подключение:
    Room: FakeDiscord
    Passphrase: HelldiversDissidents

Главное отличие
---------------
Windows Terminal больше НЕ нужен.

Tincan запускается внутри ConPTY, а FakeDiscord сам:
1. получает VT/ANSI-вывод Tincan;
2. разбирает escape-последовательности;
3. рисует терминал в своём Win32-окне;
4. ловит клавиши напрямую;
5. отправляет Tincan xterm-compatible key sequences.

Это должно исключить проблему, при которой Windows Terminal/Console Host
через некоторое время перестаёт отдавать Tincan F2/F3/F5/F6.

Сборка
------
1. Установи Visual Studio Build Tools 2022:
   - Desktop development with C++
   - Windows 10/11 SDK

2. Положи Windows x64 tincan.exe рядом с файлами проекта.

3. Открой:
   x64 Native Tools Command Prompt for VS 2022

4. Перейди в папку проекта.

5. Запусти:
   build_msvc.bat

6. Получишь:
   FakeDiscord.exe

Друзьям нужен только FakeDiscord.exe.

Требования Windows
------------------
ConPTY появился в Windows 10 version 1809.
Практически: Windows 10 1809+ или Windows 11.

Текущие ограничения прототипа
-----------------------------
Это НЕ полноценный Windows Terminal.

Реализован набор VT-команд, достаточный для типичного ratatui/crossterm TUI,
но редкие escape-последовательности могут отображаться неправильно.

Пока не реализованы:
- мышь внутри TUI;
- hyperlinks/OSC 8;
- sixel/kitty graphics;
- полноценный grapheme/combining renderer;
- IME-редактор;
- scrollback истории.

Для Tincan это не должно быть критично: его интерфейс в основном использует
обычный alternate-screen TUI, текст, цвета, курсор и F-клавиши.

Если в конкретном месте Tincan что-то рисует неправильно — пришли скриншот:
можно добавить недостающую VT-команду в TerminalBuffer.cpp без увеличения
приложения на десятки мегабайт.

Безопасность
------------
Passphrase быстрого подключения HelldiversDissidents зашит в EXE.
Его нельзя считать секретом от человека, у которого есть бинарник.

При распространении встроенного tincan.exe сохрани MIT license notice
из используемого релиза Tincan.

ИСПРАВЛЕНИЕ v8 — стабильная база от v6
---------------------------------------
- v8 сделана заново от последней реально собирающейся v6, а не поверх сломанной v7.
- Prompt больше не использует отдельный STATIC-контрол: подпись формы рисует само окно,
  поэтому старые кнопки/надписи не должны проступать под новым экраном.
- Форма ввода размещается в отдельной тёмной карточке по центру.
- ConPTY больше не вызывает repaint на каждый кусок вывода. Используется UI-таймер ~30 FPS.
- При реальном изменении числа строк/колонок терминальный буфер очищается, ConPTY получает resize,
  что уменьшает "съезжание" и остатки старой геометрии Tincan.
- Esc в голосовом режиме по-прежнему возвращает в главное меню и завершает Tincan.

ИСПРАВЛЕНИЕ v10 — собственное окно подтверждения
-------------------------------------------------
При Esc в голосовом чате системный MessageBox больше не используется.

ИСПРАВЛЕНИЕ v11 — Clipboard
---------------------------
В собственном терминале FakeDiscord теперь работает вставка из буфера обмена:

- Ctrl+V
- Ctrl+Shift+V (также срабатывает как Ctrl+V)
- Shift+Insert

FakeDiscord читает CF_UNICODETEXT из Windows Clipboard, преобразует Unicode
в UTF-8 и отправляет содержимое в Tincan через ConPTY.

Переносы строк CRLF/LF нормализуются в CR, чтобы вставка многострочного текста
вела себя как обычный ввод через Enter в терминале.

Ctrl+C специально остаётся управляющей комбинацией Tincan, а не командой
копирования, поскольку у терминального рендерера пока нет выделения текста.


ИСПРАВЛЕНИЕ v12 — выделение и копирование
-----------------------------------------
Добавлено выделение текста в собственном терминале:

- ЛКМ + перетаскивание — выделение текста.
- Выделение подсвечивается фиолетово-серым фоном.
- Ctrl+C при наличии выделения — копирование в Windows Clipboard.
- Ctrl+C без выделения в голосовом терминале по-прежнему отправляет ^C Tincan.
- ПКМ при наличии выделения — копирует выделенный текст.
- Работает также на экране "Аудиоустройства".
- Многострочное выделение копируется с CRLF.
- Пустые пробелы в конце строк не добавляются в Clipboard.
- При изменении размера окна выделение сбрасывается.


V13 — РАЗДЕЛЕНИЕ ПРОЕКТА НА МОДУЛИ
-----------------------------------
FakeDiscord.cpp больше не содержит весь проект целиком.

Структура:

- Clipboard.*               — Windows Clipboard и вставка в ConPTY.
- DisconnectDialog.*        — собственное окно подтверждения "Отключиться?".
- Win32Config.h             — общие настройки Win32/MSVC.

Также исправлена текущая ошибка MSVC std::clamp: координаты RECT (LONG)
больше не передаются в std::clamp вместе с int. В модуле TerminalSelection
границы RECT сначала явно преобразуются в int.


Дополнительно вынесено:

- TextUtil.*               — UTF-8/UTF-16 и переменные окружения.


ИСПРАВЛЕНИЕ v14
----------------
Исправлена компиляция TerminalSelection.cpp под MSVC:

POINT.x / POINT.y имеют тип LONG, а границы выделения хранятся как int.
std::clamp требует одинаковый тип всех трёх аргументов, поэтому координаты
мыши теперь сначала явно преобразуются в int, clamp выполняется только над int,
после чего значение при необходимости записывается обратно в POINT как LONG.

Также расчёт row/col использует уже нормализованные int pointX/pointY.


ИСПРАВЛЕНИЕ v15 — сброс выделения
----------------------------------
Выделение текста теперь не остаётся навсегда:

- после успешного Ctrl+C выделение снимается;
- после успешного копирования ПКМ выделение снимается;
- новый клик ЛКМ начинает новое выделение с чистого состояния;
- внутренние координаты старого выделения сбрасываются.


ИСПРАВЛЕНИЕ v16 — ПКМ copy/paste
---------------------------------
ПКМ теперь работает контекстно:

- есть выделение -> ПКМ копирует выделенный текст в Windows Clipboard;
- после успешного копирования выделение сразу снимается;
- выделения нет + в Clipboard есть Unicode-текст -> ПКМ вставляет его в Tincan;
- Clipboard пустой / текстового формата нет -> ПКМ ничего не делает.

Ctrl+C при наличии выделения также копирует текст и снимает выделение.
Ctrl+C без выделения по-прежнему передаётся Tincan как ^C.

Также исправлена ошибка v15 в ClearSelection(): использовалось несуществующее
поле selectionActive_. Теперь ClearSelection() вызывает штатный Clear().


ИСПРАВЛЕНИЕ v17 — Tincan TUI / Tab / VT autowrap
-------------------------------------------------
Исправлена причина разрушения интерфейса Tincan после Tab/смены канала.

Раньше TerminalBuffer сразу делал LineFeed при записи символа в последнюю
колонку. Настоящий VT/xterm использует delayed autowrap: курсор остаётся
в последней колонке, а перенос выполняется только при следующем печатном
символе. TUI Tincan при полном redraw рассчитывает именно на это поведение.

Добавлено:
- delayed wrap / wrap-pending;
- DEC autowrap mode CSI ? 7 h / CSI ? 7 l;
- DEC origin mode CSI ? 6 h / CSI ? 6 l;
- корректное CUP/HVP/VPA относительно scroll region при origin mode;
- сброс wrap-pending при CR, LF, Backspace, Tab, cursor movement,
  erase/insert/delete и смене экрана;
- DECSTBM теперь возвращает курсор в корректный home с учётом origin mode.

Сам Tab по-прежнему передаётся Tincan как обычный \t — костыль на клавишу
не добавлялся.


ИСПРАВЛЕНИЕ v18 — Ctrl+C / выход из чата
-----------------------------------------
Изменено поведение Ctrl+C в голосовом терминале:

- если есть выделение текста: Ctrl+C копирует выделение;
- если выделения нет: Ctrl+C НЕ отправляется Tincan как ^C;
- FakeDiscord сам завершает текущую ConPTY/Tincan-сессию;
- после этого сразу открывается обычное главное меню FakeDiscord.

Это убирает промежуточный собственный экран Tincan "connecting to the room...",
который раньше оставался на экране после Ctrl+C.

Esc по-прежнему использует кастомное окно подтверждения "Отключиться?".


ЭКСПЕРИМЕНТАЛЬНАЯ ПЕРЕДАЧА ФАЙЛОВ — fd2
=========================================
В эту отдельную ветку встроен модифицированный Tincan 0.3.2-fd2.
Стабильный проект FakeDiscord_Native_CPP не изменялся.

Передача файлов работает напрямую между участниками через отдельный iroh/QUIC ALPN.
Координатор комнаты пересылает только метаданные предложения файла.

Команды внутри чата:
  /send <путь>   — предложить файл участникам текущего канала
  /files         — показать последние предложения файлов
  /get <id>      — скачать выбранный файл

Примеры Windows:
  /send C:\Users\Admin\Downloads\test.zip
  /files
  /get ab12cd34

Полученные файлы сохраняются в:
  %USERPROFILE%\Downloads\FakeDiscord

Путь можно переопределить переменной:
  FAKEDISCORD_DOWNLOAD_DIR

Перед окончательным сохранением проверяется BLAKE2s-256.
Существующие файлы не перезаписываются: к имени добавляется номер.
Максимальный размер одного файла в текущем прототипе: 8 GiB.

ВАЖНО ПО СОВМЕСТИМОСТИ
-----------------------
Этот build использует tincan/control/2. Обычный Tincan 0.3.2 использует старый
control protocol и с экспериментальным build несовместим. Все участники комнаты
должны использовать FakeDiscord/Tincan из этой экспериментальной папки.

ARCH LINUX
----------
Исходники общего Rust-core находятся в tincan-src.
Arch-реализация и скрипты находятся в arch-linux.
Подробная инструкция: arch-linux/README_ARCH_RU.md

Зависимости Arch:
  sudo pacman -S --needed base-devel rust pkgconf alsa-lib opus

Сборка:
  bash arch-linux/build_arch.sh

Установка:
  bash arch-linux/install_arch.sh

После установки:
  fakediscord


НОВОЕ В fd2 — DRAG'N'DROP И /send + TAB
========================================
Windows:
  Перетащи один или несколько файлов прямо в окно активной сессии FakeDiscord.
  Launcher автоматически переключит Tincan на Chat (F5) и отправит для каждого:
    /send "<полный путь>"

  Папки при drag'n'drop игнорируются.

Windows + Arch Linux:
  Tab после /send работает как файловое автодополнение:
    /send
    <Tab>

    /send D:\Dow
    <Tab>

    /send ~/Down
    <Tab>

  Поддерживаются:
  - абсолютные и относительные пути;
  - домашний каталог ~;
  - Unicode;
  - пробелы в путях;
  - последовательный переход по каталогам;
  - несколько совпадений с общим префиксом и подсказкой в status-line.

  Обычный Tab, если строка не является /send, по-прежнему переключает канал.


НОВОЕ В fd3 — /get + TAB
========================
Для уже опубликованных файлов Tab теперь работает и с /get:

  /get
  <Tab>
    -> показывает доступные файлы текущего канала

  /get ab12
  <Tab>
    -> дополняет transfer ID

  /get screenshot
  <Tab>
    -> ищет по части имени файла и при единственном совпадении
       заменяет ввод на /get <id>

Если совпадений несколько, варианты выводятся в status-line.
